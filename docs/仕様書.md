# MySchedule 仕様書

**現行実装を正とする。** 機能・パラメータ・色・APIを変えたら、本書の該当箇所も同じターンで更新すること。

## 1. 概要と構成理由

Excel「時間記録.xlsx」を置き換える個人用スケジュール管理Webアプリ。
月ごとの30分単位タイムグリッド(横=日付、縦=時刻)に区分を塗って予定・実績を管理し、区分別の月間集計と勤務日数・要求時間の比較を自動計算する。**主目的は今後の予定管理(8割)、時間集計は従(2割)。**

**採用構成**: GitHub Pages(フロント静的サイト) + GAS(JSON API) + Googleスプレッドシート(データ)。利用者は本人のみ。

- 採用理由: フロントを外部ホストに置き、GASを「開発者権限で動くAPI」に特化させる visit-map で実績のある構成。スマホでも**GoogleログインなしでURLを開くだけ**で使える/Googleカレンダー連携・祝日取得はGAS標準API(CalendarApp)で認証実装不要/データはスプレッドシートに残り目視・手修正できる/コードはGitHubで版管理/無料
- **やめた案**:
  - GAS HtmlService 配信(当初実装) — 開くたびにGoogleログインが必要でスマホで使いにくい。GitHubでの版管理・配信と両立しないため、フェーズ2完了時点でPages+API構成に変更した
  - ローカル完結型(単一HTML+ブラウザ内DB) — カレンダー連携にGCPでのOAuth設定が必要で重く、ブラウザデータ削除で消えるリスク
  - React SPA+バックエンド — 個人用途にはホスティング・認証の手間が過剰
- 予定と実績は**1グリッド上書き運用**(Excelと同じ。予定を塗り、実際が違ったらその場で直す)。別レイヤー管理は入力が倍になるため不採用

## 3. システム構成・通信

```
ブラウザ(GitHub Pages: index.html + style.css + app.js)
  │  fetch POST(Content-Type: text/plain → CORS preflight回避)
  │  body: {"token": "...", "fn": "関数名", "args": [...]}
  ▼
GAS doPost (コード.gs) … tokenを設定シートのapiTokenと照合。不一致は全拒否
  ├─ SpreadsheetApp → スプレッドシート6シート
  └─ CalendarApp   → 日本の祝日カレンダー(年単位取得→祝日シートにキャッシュ)
  レスポンス: {"ok": true, "data": ...} | {"ok": false, "error": "..."}
```

- **CORS**: GASはpreflight(OPTIONS)に応答できないため、`text/plain` のsimple requestにする。GASの302リダイレクトはfetchが自動追従し、最終レスポンスに `Access-Control-Allow-Origin: *` が付く(匿名アクセス許可時)
- **認証**: `apiToken`(設定シート、初期化時にUUID自動生成)。`readConfig_()` はapiTokenを**フロントへ返さない**。漏洩時はシートの値を変えるだけで即無効化
- **API設定の保持**: フロントはGAS URL+トークンを初回入力→`localStorage`(キー `myschedule-api`)。コードにはハードコードしない(Publicリポのため必須)
- 通信失敗は共通 `handleServerError`(トースト)。認証系エラーは設定モーダル(⚙)へ誘導。保存失敗はdirtyを戻しステータス表示クリックで手動再送
- 祝日取得失敗はサーバー側で握りつぶし、キャッシュで動作継続(アプリは止めない)
- **祝日フィルタ**: Googleの祝日カレンダーは「七夕」「大晦日」等の行事も含むため、イベント説明欄に「祝日」を含むもののみ法定祝日として採用(営業日計算が狂うのを防ぐ)。「祝日」表記が1件も無い場合は全件採用にフォールバック
- モック: `window.__MYSCHEDULE_MOCK__` が定義されていると `serverCall` は通信せずそちらを呼ぶ(preview/専用)

## 5. データモデル(スプレッドシート)

### 変更禁止事項
- **列の挿入・順序変更は禁止。追加は末尾のみ**(サーバーが列位置直読みのため破壊的)
- 記録A:B列・日次A列・祝日A列は**テキスト書式(@)固定**(日付・時刻が数値/日付型に自動変換されるとデータが壊れる)。`setupSpreadsheet()` が書式を設定する
- 日付は `yyyy-MM-dd`、時刻は `HH:mm` の文字列。読み取りは寛容(Date型・スラッシュ区切りも解釈)、保存時に正規化

### シート定義

| シート | 列 | 備考 |
|---|---|---|
| `設定` | キー / 値 / 説明 | 下記「主要パラメータ」参照。**apiTokenを含む(フロントへは返さない)** |
| `区分` | コード / 名称 / 親コード / 色 / 表示順 / 有効 | 親コード空=大区分、あり=内訳。色空の内訳は親の色で表示。有効=チェックボックス |
| `記録` | 日付 / 時刻 / 区分 / 内訳 / メモ | 1行=1スロット(30分)。区分なし行は保存されない |
| `日次` | 日付 / 有休 / 日メモ | 有休・メモとも空の日は保存されない |
| `祝日` | 日付 / 名称 | 年単位キャッシュ(**表示年+翌年**を自動確保)。手動編集可(その年を消せば再取得) |
| `取込対応` | タイトル / 区分 / 内訳 | カレンダー取込の区分ルール。タイトル列は**キーワード**として扱い、完全一致→部分一致の順で照合する(初期値: 築地出社/テレワーク/UB/神谷町→UB、奉仕→FS、BRV→BT、集会→MT。不足行は起動時に補われるが既存行は変更しない)。終日イベント(日メモ取込)は区分列に予約語 **`DAYMEMO`**。手で行を足せばルールを追加できる |

### 区分マスタ初期値
UB(派遣先業務)/CN(自社業務)/BT(ベテル奉仕)/FS(奉仕)/MT(集会)/CW(会衆の仕事)/ST(勉強: 個人研究・割当準備・聖書通読・集会予習)/FX(フレックス: 料理・掃除・洗濯・エクササイズ・レク)/mv(移動)。
コードは仮置きであり、アプリの区分編集画面から変更可能(**ただしコード自体は追加後変更不可**。過去記録との不整合を防ぐため。名称・色・表示順・有効は変更可)。

## 6. API仕様

エンドポイント: GAS WebアプリURL(…/exec)。すべて `POST {token, fn, args}` 形式。

| fn | args | data(返り値) | 説明 |
|---|---|---|---|
| `getMonthData` | `['yyyy-MM']` | `{ym, config, categories, records[], days[], holidays{}}` | 月データ一括取得。シート未作成なら自動セットアップ、祝日はその年ぶんを自動取得 |
| `saveMonthRecords` | `[ym, [{date,time,code,sub,memo}]]` | `{ok, savedYm}` | **月ブロック置換**: 対象月の行を丸ごと差し替え、日付時刻順で書き戻し |
| `saveMonthDays` | `[ym, [{date,paidLeave,memo}]]` | `{ok, savedYm}` | 同上(日次) |
| `saveCategories` | `[categories]` | `{ok, count}` | 全置換 |
| `listCalendarEvents` | `['yyyy-MM']` | `{events[], importMap}` | その月のカレンダー予定一覧(メインカレンダー+設定`calendarIds`。祝日カレンダーは対象外)+タイトル→区分の記憶 |
| `saveImportMap` | `[[{title,code,sub}]]` | `{ok, count}` | タイトルでupsert(取込対応シート) |
| `listWeekData` | `['yyyy-MM-dd', 'yyyy-MM-dd']`(from含む・to含まず、1〜14日) | `{events[], tasks[], tasksAvailable, holidays{}}` | 週ビュー用一括取得。eventsは各要素に`recurring`(繰り返し予定か)を含む。tasksはGoogle Tasks高度なサービスから期限が範囲内の未完了タスク(`{title, due, listName}`)。Tasksサービス未有効でも落ちず `tasks:[], tasksAvailable:false` を返す。holidaysは範囲内の祝日 |

- `GET`(ブラウザで開く)は死活確認用JSON(`{ok:true, app:'MySchedule API'}`)
- `setupSpreadsheet()` はGASエディタから手動実行も可(冪等)

## 7. UX・ロジックの統一ルール(改修時に踏襲)

- **保存の型**: UI即時反映(楽観更新) → `markRecordsDirty()/markDaysDirty()` → 1.2秒デバウンス → 月まるごと送信。ステータス表示は「変更あり…→保存中…→保存済み/保存失敗(クリックで再試行)」。区分保存のみ即時(モーダル操作のため)
- **エラーの型**: すべて `handleServerError()` 経由でトースト表示。自動リトライはしない。認証系エラーのみ設定モーダルを開く
- **更新粒度**: 状態変更(塗り・メモ・有休・区分変更)は `renderGrid()`+`renderSummary()` の再描画。ドラッグ中のプレビューのみクラス付け外しの部分更新
- **Esc**: 最前面から1つずつ閉じる(ポップオーバー → パレットの内訳メニュー → モーダル)。オーバーレイクリック・外側クリックでも閉じる
- **表示/非表示は `hidden` 属性で制御**: style.css 冒頭の `[hidden] { display: none !important; }` が前提。これが無いと display:flex 指定要素(モーダルオーバーレイ・読み込み中表示)が hidden でも表示され続け画面を覆う(公開直後に実際に起きたバグ)
- **色**: 土=淡青 / 日祝=淡赤 / 有休=淡黄(列全体)。今日=オレンジ枠。セルの区分色はマスタの色(内訳で色空欄は親を継承)
- **セル表示**: メモがあればメモ(赤三角マーク付き)、なければ内訳名 or 区分コード。詳細はツールチップ
- **操作**: 塗り=パレット選択→クリック/矩形ドラッグ。メモ=セル右クリック(同区分連続枠への一括適用が既定ON)。日情報=日ヘッダクリック。塗り直し時はメモを引き継がない(区分とメモの食い違い防止)
- **なぞって消す(トグル消去)**: ドラッグ開始セルが「選択中の区分・内訳と同じ」なら、その矩形は消去になる(消しゴム不要)。別区分ならそのまま上書き。判定はドラッグ開始時に確定し、プレビュー枠の色で示す(塗り=橙 / 消去=赤)
- **Undo**: 塗り・消去・メモ・日情報・カレンダー取込の変更直前のスナップショットを最大30件保持(`btn-undo` / Ctrl+Z)。**月を切り替えるとクリア**(別の月の状態に戻る事故を防ぐ)。区分マスタ編集はサーバー保存済みのためUndo対象外。値が変わらない操作は履歴に積まない
- **パレットの折りたたみ**: 「≡ 区分」ボタンで開閉し、状態を localStorage(`myschedule-palette`)に保存。未設定時は画面幅700px未満なら畳んだ状態で開始(スマホでツールバーが場所を取らないように)
- **カレンダー取込**(ツールバー「取込」): `listCalendarEvents` で表示月の予定一覧をチェック選択式で表示。**区分の推定**は取込対応シートを「完全一致→部分一致(複数該当ならキーワードが長い=具体的な方)」で引き、当たればチェックON+区分を自動選択(部分一致は「推定」バッジで完全一致と区別)。当たらなければチェックOFF+区分未選択。推定どおりに取り込んだ場合は記憶を増やさない(既存ルールで足りるため。**ルールと違う区分を選んだときだけ**そのタイトルを完全一致で覚え、次回から個別に優先される)。時間付きは30分丸め(開始切り下げ・終了切り上げ、日またぎは開始日23:59で打ち切り)でスロットへ**上書き**、終日は日メモへ「・」区切りで**冪等追記**(同一文字列があればスキップ)。時間帯外(dayStart前/dayEnd後)のスロットも生成する(9章の既存仕様どおり表示されないが集計に含まれる)。取込全体を`pushUndo("both")`で1回のUndoにまとめる。タイトル→区分の対応は`saveImportMap`で記憶し次回自動提案するが、この記憶保存自体はUndo対象外(残っても実害なし)
- **週ビュー**(ツールバー「月/週」トグル): 読み取り専用。表示状態は`localStorage`(`myschedule-view`)に永続化し、次回起動時も引き継ぐ。週ビュー中はツールバーの前後ナビ・「今日」ボタンが週送り(月曜始まり)・今週表示に切替わり、ラベルは「7/27〜8/2」形式(`M/D〜M/D`)。データは`listWeekData`で週単位取得: 繰り返し予定=薄い全幅の背景帯(`wk-base`。同じ日でベース同士が時間重複する場合、後発を幅70%・右寄せ(left:30%)+前面(z-index高)にして重なりを示す)、単発予定=白背景+濃枠+影の前面カード(`wk-card`。表示エリアは日カラムの右85%、カード同士が時間重複する場合のみそのクラスタ内で列分割して左右に並べる)、終日予定とタスクは日カラム上部のストリップ(`wk-day-strip`)にバッジ表示。時間軸はconfigの`dayStart`〜`dayEnd`を基準にしつつ、はみ出す予定があれば時間単位(時)で自動拡張。土日・祝日の色分けは月表示と同じ(`dayClass`)だが**有休による色分けはしない**(週ビューは日次データの有休フラグを見ずに描画するため)。週データはセッション内メモリキャッシュ(`weekCache`、週の開始日をキーにしたMap)で週切替時の再取得を抑制し、「⟳」ボタン(`btn-week-reload`)でその週のキャッシュを破棄して再取得できる。読み込みエラーは月表示と同じ`handleServerError()`経由でトースト表示。Google Tasks高度なサービスが未有効な場合はタスク欄に案内(`week-tasks-note`)を表示する

## 8. 集計仕様

- **日ごとの合計**: グリッド最下部に `clientWorkCode`(既定UB)の日次合計を固定表示(tfoot、sticky)。0の日は薄いグレーで「0」。月間集計のUB実績と一致する
- 区分別: 親区分の時間(=直塗り+内訳合算)と全体比%、内訳ごとの小計。0時間の区分は非表示
- **勤務日数 = 営業日(月〜金 − 祝日) − 有休日数**
- **契約人月係数** `manMonthRatio`(既定0.6 = 0.6人月契約)を要求時間に乗じる:
  自社要求 = 勤務日数 × `ownHoursPerDay`(既定8.0) × 係数、派遣先要求 = 勤務日数 × `clientHoursPerDay`(既定7.5) × 係数
  (検算例: 勤務日数21日 → 派遣先要求 21×7.5×0.6 = 94.5h。係数1のときはラベルの「×0.6」表示を省略)
- `clientWorkCode`(既定UB)の実績合計を両要求と比較し、差分を±表示

## 9. 既知の制約・注意点

- リポジトリはPublic(無料Pagesの条件)。**公開されるのはコードのみ**。データ・トークン・GAS URLは含めないこと(レビュー時の確認観点)
- GASは「全員」アクセスだが、apiToken不一致はすべて拒否。トークンは設定シートで即時変更可能
- 排他ロックなし(利用者1人前提)。**複数タブ・複数端末の同時編集は非推奨**(後勝ち上書き)
- 保存は「月まるごと置換」のため、記録シートを開いたまま手動編集した内容は次の保存で上書きされうる(手動編集はアプリを閉じて行う)
- スマホは閲覧できる程度(塗り操作はPCのマウス前提)。本格対応はフェーズ4
- 祝日はGoogleカレンダー依存。取得失敗時は祝日なしとして扱われる(翌回アクセスで再試行)
- グリッド時間帯外(dayStart前・dayEnd後)の記録は画面に表示されないが、データは保持され集計には含まれる
- 週ビューは日またぎ予定を開始日のみに表示し、終了は当日24:00で打ち切り(前日から当日に食い込む予定は表示されない)。タスクの完了操作はできない(表示のみ)
