# MySchedule 仕様書

**現行実装を正とする。** 機能・パラメータ・色・APIを変えたら、本書の該当箇所も同じターンで更新すること。

## 1. 概要と構成理由

Excel「時間記録.xlsx」を置き換える個人用スケジュール管理Webアプリ。
月ごとの30分単位タイムグリッド(横=日付、縦=時刻)に区分を塗って予定・実績を管理し、区分別の月間集計と勤務日数・要求時間の比較を自動計算する。**主目的は今後の予定管理(8割)、時間集計は従(2割)。**

**採用構成**: Cloudflare Workers(Static Assetsでフロント配信) + D1(SQLite、データ) + GASプロキシ(Googleカレンダー・Google Tasksの窓口)。利用者は本人のみ。

- 採用理由: フロントとAPIを同一オリジン(Workers Static Assets)で配信しCORSプリフライトを回避/D1は無料枠で完結/`wrangler deploy`でコード・スキーマ変更を自動デプロイでき手作業のGASデプロイが減る/1日1行へのJSON畳み込み(`days`テーブル)でスプレッドシートの行増殖を回避/Googleカレンダー・Tasksの認証実装は既存GASプロジェクトへの委譲(`gas/calendar_proxy.gs`)で不要のまま維持
- **やめた案**:
  - GitHub Pages(フロント) + GAS(JSON API) + Googleスプレッドシート(データ)(2026-07-22〜2026-08-02採用、フェーズ5でカットオーバー) — スプレッドシート版は1スロット1行のため記録シートの行数が増え続け、GASのデプロイも手作業だった。詳細は `docs/DB設計.md`・`docs/構築手順書.md` 参照
  - GAS HtmlService 配信(当初実装) — 開くたびにGoogleログインが必要でスマホで使いにくい
  - ローカル完結型(単一HTML+ブラウザ内DB) — カレンダー連携にGCPでのOAuth設定が必要で重く、ブラウザデータ削除で消えるリスク
  - React SPA+バックエンド — 個人用途にはホスティング・認証の手間が過剰
- 予定と実績は**1グリッド上書き運用**(Excelと同じ。予定を塗り、実際が違ったらその場で直す)。別レイヤー管理は入力が倍になるため不採用

## 3. システム構成・通信

```
ブラウザ(Cloudflare Workers Static Assets: web/index.html + web/style.css + web/app.js)
  │  fetch POST /api(Content-Type: text/plain。同一オリジンのためCORS不要)
  │  body: {"token": "...", "fn": "関数名", "args": [...]}
  ▼
Cloudflare Worker(worker/src/index.js) … tokenをWorkers Secret API_TOKENと照合。不一致は全拒否
  ├─ D1(SQLite) → days/categories/config/import_map/holidays
  └─ worker/src/gasProxy.js → GASプロキシ(gas/calendar_proxy.gs)へサーバー側fetch → CalendarApp/Tasks
  レスポンス: {"ok": true, "data": ...} | {"ok": false, "error": "..."}
```

- **CORS**: フロントとAPIが同一オリジン(Cloudflare Workers)のため不要。旧GitHub Pages併用期(フェーズ5移行期間中)の互換のため `text/plain` かつCORSヘッダーの付与は維持している
- **認証**: `API_TOKEN`(Workers Secret)。フロントが送る `token` と照合。漏洩時は `wrangler secret put API_TOKEN` で値を変えれば即無効化。GASプロキシ側は `PROXY_TOKEN`(Script Properties)で別途認証(`GAS_TOKEN` としてWorkerがサーバー側から照合)
- **API設定の保持**: フロントはAPI URL(Worker `/api`)+トークンを初回入力→`localStorage`(キー `myschedule-api`)。コードにはハードコードしない(Publicリポのため必須)
- 通信失敗は共通 `handleServerError`(トースト)。認証系エラーは設定モーダル(⚙)へ誘導。保存失敗はdirtyを戻しステータス表示クリックで手動再送
- 祝日取得失敗はサーバー側で握りつぶし、キャッシュで動作継続(アプリは止めない)
- **祝日フィルタ**: Googleの祝日カレンダーは「七夕」「大晦日」等の行事も含むため、イベント説明欄に「祝日」を含むもののみ法定祝日として採用(営業日計算が狂うのを防ぐ)。「祝日」表記が1件も無い場合は全件採用にフォールバック
- モック: `window.__MYSCHEDULE_MOCK__` が定義されていると `serverCall` は通信せずそちらを呼ぶ(preview/専用)
- **Worker→GASプロキシ**(`worker/src/gasProxy.js`): タイムアウト`GAS_TIMEOUT_MS`(12秒)。失敗時は`GAS_RETRY_WAIT_MS`(500ms)待って1回だけ自動リトライする
- **listWeekDataのキャッシュ**(`worker/src/actions/listWeekData.js`): GASから返る`events`/`tasks`/`tasksAvailable`をWorkerのアイソレートメモリに`WEEK_DATA_CACHE_TTL_MS`(5分)保持(上限`WEEK_DATA_CACHE_MAX_ENTRIES`=50件)。ヒット時はGASを呼ばず、祝日(`holidays`)だけD1から都度合成して返す。第4引数`fresh`(truthy)を渡すとキャッシュをバイパスする(⋯メニューの「⟳再読込」が使用)

## 5. データモデル(D1/SQLite)

D1のDDL・`days`テーブルへのスロットJSON畳み込み仕様の詳細な正は `docs/DB設計.md` §3(スキーマ)・§2(fn別の畳み込み/展開の差分)。以下は要約。

### 変更禁止事項
- **スキーマ変更は `worker/migrations/` へ新規SQLファイルを追加して行う。既存マイグレーションファイルの書き換えは禁止**(適用済み環境との不整合を防ぐため)
- 日付は `yyyy-MM-dd`、時刻は `HH:mm` の文字列(Date型を状態に持ち込まない)

### テーブル定義(要約。DDLは `docs/DB設計.md` §3)

| テーブル | 列 | 備考 |
|---|---|---|
| `config` | key / value / note | 下記「主要パラメータ」参照。`dayStart`/`dayEnd`/`ownHoursPerDay`/`clientHoursPerDay`/`clientWorkCode`/`manMonthRatio`/`calendarIds`。**apiTokenは含まない(Workers Secret `API_TOKEN` へ移行済み)** |
| `categories` | id / code / name / parent / color / sort / active | 親コード空=大区分、あり=内訳。色空の内訳は親の色で表示。全置換運用(`saveCategories`) |
| `days` | date(PK) / slots(JSON) / paid_leave / memo | 1行=1日。`slots`は`{"HH:mm":{"code","sub","memo"}}`のJSONで、旧「記録」(1行=1スロット)を1日分に畳み込んだもの。`slots='{}'`かつ`paid_leave=0`かつ`memo=''`の行は保存されない(旧仕様の踏襲) |
| `import_map` | title(PK) / code / sub | カレンダー取込の区分ルール。タイトル列は**キーワード**として扱い、完全一致→部分一致の順で照合する(初期値: 築地出社/テレワーク/UB/神谷町→UB、奉仕→FS、BRV→BT、集会→MT。不足行はマイグレーションseedで補われるが既存行は変更しない)。終日イベント(日メモ取込)は区分列に予約語 **`DAYMEMO`**。手でupsertすればルールを追加できる |
| `holidays` | date(PK) / name | 年単位キャッシュ(**表示年+翌年**を自動確保)。GASプロキシ`getHolidays`から補充。D1コンソールで手動編集可(その年を消せば再取得) |

旧スプレッドシート版の6シート(設定・区分・記録・日次・祝日・取込対応)は**移行後もアーカイブとして温存**(読み取り専用・編集しない。移行手順は `docs/DB設計.md` §8・`docs/構築手順書.md` §3)。

### 区分マスタ初期値
UB(派遣先業務)/CN(自社業務)/BT(ベテル奉仕)/FS(奉仕)/MT(集会)/CW(会衆の仕事)/ST(勉強: 個人研究・割当準備・聖書通読・集会予習)/FX(フレックス: 料理・掃除・洗濯・エクササイズ・レク)/mv(移動)。
コードは仮置きであり、アプリの区分編集画面から変更可能(**ただしコード自体は追加後変更不可**。過去記録との不整合を防ぐため。名称・色・表示順・有効は変更可)。

## 6. API仕様

エンドポイント: Cloudflare WorkerのURL(`https://<worker名>.workers.dev/api`)。すべて `POST {token, fn, args}` 形式。

| fn | args | data(返り値) | 説明 |
|---|---|---|---|
| `getMonthData` | `['yyyy-MM']` | `{ym, config, categories, records[], days[], holidays{}}` | 月データ一括取得。D1の`days`テーブルからslotsを`records[]`形式に展開して返す |
| `saveMonthRecords` | `[ym, [{date,time,code,sub,memo}]]` | `{ok, savedYm}` | **月ブロック置換**: 対象月の各日について`slots`を丸ごと置換(`paid_leave`/`memo`は保持)。対象月外の日付は当該日の行へスロット単位でマージ |
| `saveMonthDays` | `[ym, [{date,paidLeave,memo}]]` | `{ok, savedYm}` | 同上(`paid_leave`/`memo`を置換、`slots`は保持) |
| `saveCategories` | `[categories]` | `{ok, count}` | 全置換 |
| `listCalendarEvents` | `['yyyy-MM']` | `{events[], importMap}` | その月のカレンダー予定一覧(WorkerがGASプロキシ`listCalendarEvents`へサーバー側fetch転送。祝日カレンダーは対象外)+タイトル→区分の記憶(D1`import_map`)。eventsの各要素に`color`(hex。イベント個別色→無ければカレンダー色。取得不可時は空文字)を含む |
| `saveImportMap` | `[[{title,code,sub}]]` | `{ok, count}` | タイトルでupsert(D1`import_map`) |
| `listWeekData` | `['yyyy-MM-dd', 'yyyy-MM-dd', fresh?]`(from含む・to含まず、1〜14日。第4引数`fresh`はtruthyでWorkerのアイソレートメモリキャッシュをバイパス) | `{events[], tasks[], tasksAvailable, holidays{}}` | 週ビュー用一括取得。eventsは各要素に`recurring`(繰り返し予定か)と`color`(hex。イベント個別色→無ければカレンダー色。取得不可時は空文字)を含む。tasksはGoogle Tasksから期限が範囲内の未完了タスク(`{title, due, listName}`)。Tasks未有効でも落ちず `tasks:[], tasksAvailable:false` を返す。holidaysはD1`holidays`から範囲内の祝日を返す(年単位でGASプロキシ`getHolidays`から補充キャッシュ) |

- `GET`(ブラウザで開く)は死活確認用JSON(`{ok:true, app:'MySchedule API'}`)

## 7. UX・ロジックの統一ルール(改修時に踏襲)

- **保存の型**: UI即時反映(楽観更新) → `markRecordsDirty()/markDaysDirty()` → 1.2秒デバウンス → 月まるごと送信。ステータス表示は「変更あり…→保存中…→保存済み/保存失敗(クリックで再試行)」。区分保存のみ即時(モーダル操作のため)
- **エラーの型**: すべて `handleServerError()` 経由でトースト表示。自動リトライはしない。認証系エラーのみ設定モーダルを開く。同一メッセージのトーストは`TOAST_DEDUPE_MS`(5秒)以内の連発を抑止する(タイムアウト頻発時のスパム防止)
- **更新粒度**: 状態変更(塗り・メモ・有休・区分変更)は `renderGrid()`+`renderSummary()` の再描画。ドラッグ中のプレビューのみクラス付け外しの部分更新
- **Esc**: 最前面から1つずつ閉じる(ポップオーバー → パレットの内訳メニュー → モーダル)。オーバーレイクリック・外側クリックでも閉じる
- **表示/非表示は `hidden` 属性で制御**: style.css 冒頭の `[hidden] { display: none !important; }` が前提。これが無いと display:flex 指定要素(モーダルオーバーレイ・読み込み中表示)が hidden でも表示され続け画面を覆う(公開直後に実際に起きたバグ)
- **色**: 土=淡青 / 日祝=淡赤 / 有休=淡黄(列全体)。今日=オレンジ枠。セルの区分色はマスタの色(内訳で色空欄は親を継承)
- **セル表示**: メモがあればメモ(赤三角マーク付き)、なければ内訳名 or 区分コード。詳細はツールチップ
- **操作**: 塗り=パレット選択→クリック/矩形ドラッグ。メモ=セル右クリック(同区分連続枠への一括適用が既定ON)。日情報=日ヘッダクリック。塗り直し時はメモを引き継がない(区分とメモの食い違い防止)
- **なぞって消す(トグル消去)**: ドラッグ開始セルが「選択中の区分・内訳と同じ」なら、その矩形は消去になる(消しゴム不要)。別区分ならそのまま上書き。判定はドラッグ開始時に確定し、プレビュー枠の色で示す(塗り=橙 / 消去=赤)
- **Undo**: 塗り・消去・メモ・日情報・カレンダー取込の変更直前のスナップショットを最大30件保持(`btn-undo` / Ctrl+Z)。**月を切り替えるとクリア**(別の月の状態に戻る事故を防ぐ)。区分マスタ編集はサーバー保存済みのためUndo対象外。値が変わらない操作は履歴に積まない
- **パレットの折りたたみ**: 「≡ 区分」ボタンで開閉し、状態を localStorage(`myschedule-palette`)に保存。未設定時は画面幅700px未満なら畳んだ状態で開始(スマホでツールバーが場所を取らないように)
- **カレンダー取込**(⋯メニュー内の「取込」): `listCalendarEvents` で表示月の予定一覧をチェック選択式で表示。**区分の推定**は取込対応シートを「完全一致→部分一致(複数該当ならキーワードが長い=具体的な方)」で引き、当たればチェックON+区分を自動選択(部分一致は「推定」バッジで完全一致と区別)。当たらなければチェックOFF+区分未選択。推定どおりに取り込んだ場合は記憶を増やさない(既存ルールで足りるため。**ルールと違う区分を選んだときだけ**そのタイトルを完全一致で覚え、次回から個別に優先される)。時間付きは30分丸め(開始切り下げ・終了切り上げ、日またぎは開始日23:59で打ち切り)でスロットへ**上書き**、終日は日メモへ「・」区切りで**冪等追記**(同一文字列があればスキップ)。時間帯外(dayStart前/dayEnd後)のスロットも生成する(9章の既存仕様どおり表示されないが集計に含まれる)。取込全体を`pushUndo("both")`で1回のUndoにまとめる。タイトル→区分の対応は`saveImportMap`で記憶し次回自動提案するが、この記憶保存自体はUndo対象外(残っても実害なし)
- **週ビュー**(⋯メニュー内の「月/週」トグル): 読み取り専用。表示状態は`localStorage`(`myschedule-view`)に永続化し、次回起動時も引き継ぐ。**連続日送り**: 日列(幅`WEEK_DAY_COL_WIDTH`。既定120px。style.css `.wk-day-col`の`width`と一致させる)を横方向に連続描画し、横スクロールで日をまたいで移動する(週単位の切替・スワイプ週送りは廃止)。データは`listWeekData`を7日チャンク単位(`WEEK_CHUNK_DAYS`)で取得: 起点(`weekChunkOrigin`)は起動時の今日-7日(`WEEK_INITIAL_PAST_DAYS`)、日付から所属チャンクの開始日を`chunkKeyForDate`で求める。各チャンクは`weekCache`(Map)で`{status:"queued"|"loading"|"ready"|"error", data, byDate, holidays, tasksAvailable}`を保持する状態機械で管理し、取得は同時2件まで(`WEEK_MAX_INFLIGHT`)を`weekFetchQueue`でキューイング(可視チャンクは取得優先度を上げる)。フロント`fetch`は`SERVER_CALL_TIMEOUT_MS`(25秒)でタイムアウトさせ、`weekInflight`等が枯渇するのを防ぐ。チャンクキャッシュ(`weekCache`)は上限`WEEK_CACHE_MAX_ENTRIES`(30件)で、超過分は可視範囲から遠い順に破棄する。取得失敗したチャンクは日カラムに「読み込み失敗」+再試行ボタン(`.wk-day-retry` → `retryChunk`)を表示。繰り返し予定=薄い全幅の背景帯(`wk-base`。同じ日でベース同士が時間重複する場合、後発を幅70%・右寄せ(left:30%)+前面(z-index高)にして重なりを示す)、単発予定=白背景+濃枠+影の前面カード(`wk-card`。表示エリアは日カラムの右85%、カード同士が時間重複する場合のみそのクラスタ内で列分割して左右に並べる)、終日予定とタスクは日カラム上部のストリップ(`wk-day-strip`)にバッジ表示。
  - **2ペイン構造**(フェーズ4e): `#week-container`(縦スクロール専用)直下を`.wk-hwrap`で左(時間軸`.wk-time-axis`・横スクロールを持たない通常フロー)/右(`.wk-days-scroller`・横スクロール専用)に分ける。入れ子スクロールでsticky時間軸が破綻するのを避けるための構造で、時間軸は横スクロールしても常に左端に残る
  - **曜日ヘッダー・終日/タスク帯の疑似sticky**(フェーズ4e): `.wk-day-head`/`.wk-day-strip`は`.wk-days-scroller`(横スクロール用の入れ子スクロールコンテナ)配下にあるため、CSSの`position: sticky`は`#week-container`まで届かない(ネストしたスクロールコンテナ配下ではstickyが外側コンテナに対して効かない制約)。そのためCSS stickyではなく、縦スクロール量に応じて`translateY`を同期させるJS疑似sticky(`syncWeekDayHeaderSticky`)で上部固定を実現する
  - **スナップマーカーの配置**(フェーズ4e): `scroll-snap-align`/`scroll-snap-stop`を持つスナップ領域も最近接のスクロールコンテナに捕捉されるため、`.wk-snap-marker`は`.wk-days-scroller`(入れ子スクロールコンテナ)の内側ではなく`.wk-hwrap`直下(外側)に置く。内側に置くと縦方向のスクロールスナップが無効化される
  - **高さ基準**(フェーズ4e): `#week-container`の高さは`100svh`基準(`calc(100svh - 130px)`、未対応環境は`vh`にフォールバック)。`dvh`はアドレスバーの出没で高さがガタつくため不採用
  - **時間軸**: 00:00〜24:00固定(config `dayStart`/`dayEnd`に依存する動的レンジは廃止)
  - **sticky構成**: 曜日ヘッダー(`.wk-day-head`、高さ`WEEK_HEAD_HEIGHT`=32px)と終日/タスク帯(`wk-day-strip`)は上部固定(sticky)、時刻軸(`wk-time-axis`)は左固定(sticky)。祝日名は`title`属性で表示(見出しは折り返さない)
  - **終日/タスク帯**: 固定高`WEEK_STRIP_HEIGHT`(既定26px。style.css `.wk-day-strip`/`.wk-time-axis-strip`の`height`と一致させる)。バッジは1行`text-overflow: ellipsis`で省略し、帯からはみ出す分は帯内の縦スクロール(`overflow-y: auto`)で読める。全文はバッジタップの詳細ポップオーバーで確認する。左sticky時間軸側にも同高のスペーサー(`.wk-time-axis-strip`)を置き、日列とラベルの縦位置を揃える
  - **現在時刻ライン**: 全幅の線(`wk-now-line`、#ea4335系。`.wk-grid`座標=`WEEK_HEAD_HEIGHT`+`WEEK_STRIP_HEIGHT`+分px)と今日列の●(`wk-now-dot`。`.wk-day-body`座標=分pxのみ)は共通関数`weekNowLineTops()`(`nowMinutesOfDay()`から`lineTop`/`dotTop`を同時算出)で完全同期させ、ライン・ドット・実時刻がズレないようにする。`WEEK_NOW_LINE_INTERVAL_MS`(既定1分)ごとに更新。sticky見出し(曜日ヘッダー・時刻軸)より背面になるようz-indexを設計する。線は毎分の`setInterval`更新、●はチャンク再描画時(`buildDayColumnInner`)にのみ再計算されるため位相差が生じうるが、最大1分ぶんで毎分の更新で収束する(既知の軽微事項)
  - **スリープ・バックグラウンド復帰時の追従**(フェーズ4e): `visibilitychange`で`visibilityState==="visible"`になったら常に`updateNowLinePosition()`で現在時刻ライン位置を更新し、日付が変わっていれば`state.todayStr`を更新して`rebuildWeekTodayMarkers()`(週ビュー時)/`renderGrid()`(月ビュー時)で「今日」の枠・現在時刻ラインを再構築する
  - **境界スナップ**: `#week-container`は`scroll-snap-type: y proximity`。6:00・22:00の位置に不可視のスナップマーカー(`.wk-snap-marker`、`scroll-snap-align`+`scroll-snap-stop: always`)を配置し、縦スクロールが境界に近づくと一旦停止する(1回のスクロール操作では6:00/22:00で止まり、続けてスクロールすると0時/24時側へ抜ける)。マーカーのtopは`weekLineTopPx()`で倍率(ズーム)に応じて再計算する
  - **ピンチズーム(2本指)**: `bindWeekZoomGestures`が`#week-container`上のtouchイベントを見て、指の縦間隔の変化が横間隔より大きければ縦ズーム(1時間あたりの高さ=`WEEK_PX_PER_HOUR`、範囲`WEEK_MIN_PX_PER_HOUR`〜`WEEK_MAX_PX_PER_HOUR`)、横間隔の変化が大きければ横ズーム(列幅=`WEEK_DAY_COL_WIDTH`、範囲`WEEK_MIN_COL_WIDTH`〜`WEEK_MAX_COL_WIDTH`)として扱う。操作中は`.wk-grid`にCSS `transform`を適用した軽量プレビューのみ行い、指を離した時点で実際の`WEEK_PX_PER_HOUR`/`WEEK_DAY_COL_WIDTH`を確定してグリッドを再描画する(ピンチの中点を基準に再描画後も同じ時刻・列が中点にくるよう座標を補正)。確定値は`localStorage`(`WEEK_ZOOM_KEY`=`myschedule-week-zoom`)に永続化し、次回起動時に復元する
  - **色反映**: `listCalendarEvents`/`listWeekData`が返す`color`(hex)を使い、ベース帯(`wk-base`)は`rgba(color,0.25)`背景+4px左バー、前面カード(`wk-card`)は`rgba(color,0.12)`背景+色付き枠線(`hexToRgba`)。`color`が空文字の場合は従来配色のまま
  - **詳細ポップオーバー**: 予定・終日バッジ・タスクバッジをタップすると`openPopover`(既存の型)で詳細を表示。Escは最前面から1つずつ閉じる(ポップオーバー → ⋯メニュー → パレットの内訳メニュー → モーダル)
  - **カード・バッジのテキスト**: 折り返し表示(`truncate`による省略は廃止)。ただし終日/タスク帯のバッジのみ1行ellipsis(上記)。**ただし列幅`WEEK_COMPACT_COL_WIDTH`(90px)未満の俯瞰モード時のみ`wk-base`/`wk-card`のタイトルも1行省略になる**(CSSのみで実現。JSでの文字列切り詰めはしない)
  - **今日列の強調**(フェーズ4f): 曜日ヘッダー(`.wk-day-head.is-today`)は背景`#e8a000`+白文字。列本体(`.wk-day-body.is-today`)は左右2pxの`#e8a000`縦線(`box-shadow: inset`)。土日祝の背景と同時に該当しても今日の強調がソース順(CSS定義順)で優先される(`!important`は使わない)
  - **週境界線**(フェーズ4f): 月曜列(`getDay()===1`)の`.wk-day-col`に`wk-week-start`クラスを付与し、`.wk-day-head`/`.wk-day-strip`/`.wk-day-body`の3要素に`box-shadow: inset 2px 0 0 #8a94a0`の左縦線を引く。列幅を変えないため`border`ではなく`box-shadow`を使う
  - **俯瞰モード(列幅縮小時の1行省略)**(フェーズ4f): 列幅(`WEEK_DAY_COL_WIDTH`)が`WEEK_COMPACT_COL_WIDTH`(90px)未満のとき`#week-grid`に`wk-compact`クラスが付き、`.wk-base`/`.wk-card`のタイトルが1行+ellipsisになる(通常幅では従来どおり折り返し)
  - **深夜帯(0〜6時)折りたたみ**(フェーズ4f): 既定ON。0:00〜`WEEK_NIGHT_END_MIN`(360分=6:00)を高さ`WEEK_NIGHT_BAND_PX`(18px)の帯へ線形圧縮する。座標変換`weekMinToPx`/`weekPxToMin`(第2引数`pxPerHour`は省略時`WEEK_PX_PER_HOUR`)が区分線形化されており、現在時刻ライン・現在時刻ドット・6:00/22:00スナップマーカー・初期スクロール位置はすべてこの関数経由で自動整合する
    - **トグル**: 時間軸上のボタン(`.wk-night-toggle`。折りたたみ時は帯位置に「0–6 ▸」、展開時は6:00ラベル直上に「0–6 ▴」)と、各日列の帯(`.wk-night-band`。クリック/Enter/Space)の両方で切替できる
    - 帯内で完結するイベント(`endMin<=WEEK_NIGHT_END_MIN`)は非描画で件数のみ帯に「+N」表示。跨ぎイベント(開始<6:00<終了)は圧縮座標のまま描画され、帯(`z-index`高め)の下から6:00以降の部分だけ見える
    - トグル操作時は`scrollLeft`と「scrollTopが指す時刻」を維持したまま再構築する。縦ピンチズームのアンカー補正も`weekPxToMin`/`weekMinToPx`経由で整合させる
    - 永続化: `localStorage`キー`WEEK_NIGHT_KEY`(`myschedule-week-night`。"1"=折りたたみ/"0"=展開、既定は折りたたみ)
    - `#week-grid`の高さ: 折りたたみ時`WEEK_NIGHT_BAND_PX + 18h*WEEK_PX_PER_HOUR`、展開時`24h*WEEK_PX_PER_HOUR`
  - **スクロールによる範囲拡張・縮小**: 可視範囲が描画範囲の端から`WEEK_NEAR_EDGE_DAYS`(5日)以内に近づくと、その側へ`WEEK_CHUNK_DAYS`(7日)分伸長(`prependWeekDays`/`appendWeekDays`)。総日数が`WEEK_MAX_RANGE_DAYS`(42日)を超えたら反対側を剥がし(`removeWeekDaysFromStart`/`removeWeekDaysFromEnd`)、`scrollLeft`を伸長・剥離分だけ補正して可視位置を飛ばさない
  - **ラベル追従**: 可視範囲の左端日を`WEEK_LABEL_DEBOUNCE_MS`(150ms)のデバウンスで`updateWeekLabel`が追従表示。範囲が1日なら「7/28(月)」形式、複数日にまたがれば「7/28〜8/6」形式(`M/D〜M/D`)
  - **前後ボタン・「今日」ボタン**: 前後ボタンは7日分を`scrollBy`でスムーズスクロール、「今日」は今日の列へスクロール
  - 今日を含む範囲を表示したときは今日の列へ自動的に横スクロールする
  - `#week-container`はsvh基準の高さで画面いっぱいに表示される(フェーズ4eでdvhから変更。アドレスバー出没による高さ変動を避けるため)
  - **ページ全体の横スクロール抑止**: `html, body`は`overflow-x: hidden`(週ビューでは`#week-container`側だけが横スクロールを持つ)。これが無いとモバイルでページ側が横スクロールし、sticky時間軸の前提(左固定)が崩れる
  - **スマホ表示(画面幅`WEEK_NARROW_MAX_WIDTH`=700px未満)**: 時間重複するカードを左右分割せず、重なる順に`top`+6px・`left`+6%ずつオフセットして重ね表示する(`isNarrowWeekView`/`layoutCardEventsStacked`)
  - 土日・祝日の色分けは月表示と同じ(`dayClass`)だが**有休による色分けはしない**(週ビューは日次データの有休フラグを見ずに描画するため)。「⟳」ボタン(`btn-week-reload`、⋯メニュー内。週ヘッダー行の常設ボタンは廃止)は描画中の範囲に含まれるチャンクを再取得する。読み込みエラーは月表示と同じ`handleServerError()`経由でトースト表示。Google Tasks高度なサービスが未有効な場合はタスク欄に案内(`week-tasks-note`)を表示する
- **PWA対応**: `web/manifest.webmanifest`(`display:"standalone"`、`theme_color`/`background_color`=`#2f4a6b`、アイコン192/512/512-maskable)と`web/sw.js`(オフラインキャッシュは実装せず、`fetch`イベントは何もしない=ネットワーク素通し。インストール用の最小構成)により、スマホのホーム画面に追加してアプリのように起動できる

## 8. 集計仕様

- **日ごとの合計**: グリッド最下部に `clientWorkCode`(既定UB)の日次合計を固定表示(tfoot、sticky)。0の日は薄いグレーで「0」。月間集計のUB実績と一致する
- 区分別: 親区分の時間(=直塗り+内訳合算)と全体比%、内訳ごとの小計。0時間の区分は非表示
- **勤務日数 = 営業日(月〜金 − 祝日) − 有休日数**
- **契約人月係数** `manMonthRatio`(既定0.6 = 0.6人月契約)を要求時間に乗じる:
  自社要求 = 勤務日数 × `ownHoursPerDay`(既定8.0) × 係数、派遣先要求 = 勤務日数 × `clientHoursPerDay`(既定7.5) × 係数
  (検算例: 勤務日数21日 → 派遣先要求 21×7.5×0.6 = 94.5h。係数1のときはラベルの「×0.6」表示を省略)
- `clientWorkCode`(既定UB)の実績合計を両要求と比較し、差分を±表示

## 9. 既知の制約・注意点

- リポジトリはPublic(無料Pagesの条件から継続)。**公開されるのはコードのみ**。データ・トークン・API URLは含めないこと(レビュー時の確認観点)
- Worker APIは`API_TOKEN`(Workers Secret)必須、GASプロキシは`PROXY_TOKEN`(Script Properties)必須。いずれも不一致は全拒否。トークンは`wrangler secret put`/GASのスクリプトプロパティで即時変更可能
- 排他ロックなし(利用者1人前提)。**複数タブ・複数端末の同時編集は非推奨**(後勝ち上書き)
- 保存は「月まるごと置換」のため、D1コンソールで手動編集した内容は次の保存で上書きされうる(手動編集はアプリを閉じて行う)
- 塗り操作はPCマウス前提のまま。週ビューはスマホ実用化済み(2026-08-01)
- 祝日はGoogleカレンダー依存。取得失敗時は祝日なしとして扱われる(翌回アクセスで再試行)
- グリッド時間帯外(dayStart前・dayEnd後)の記録は画面に表示されないが、データは保持され集計には含まれる
- 週ビューは日またぎ予定を開始日のみに表示し、終了は当日24:00で打ち切り(前日から当日に食い込む予定は表示されない)。タスクの完了操作はできない(表示のみ)
