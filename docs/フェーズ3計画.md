# フェーズ3実装計画: Googleカレンダー取込

実装前に必読: [仕様書.md](仕様書.md) の「3. システム構成・通信」「5. データモデル」「7. UX統一ルール」、
および `.claude/skills/myschedule-dev/SKILL.md`(進め方・落とし穴)。
本計画はユーザー確認済みの仕様判断を含む。**ここに書かれた範囲を超える機能追加はしない**(YAGNI)。

## 目的

Googleカレンダーの予定をMyScheduleのグリッドへ取り込み、二重管理を解消する。
カレンダーには「燃えるごみの日」など予定でない記載も混ざるため、**チェック選択式**で取り込むものだけを選ぶ。
タイトル→区分の対応は記憶し、次回から自動提案する。

## 確定済みの仕様判断(ユーザー確認済み・変更しない)

1. **終日イベントは「日メモとして取込可」**: チェックしたものだけ日メモ(日次シートの日メモ欄)へ。ゴミの日はチェックしなければ無視される
2. **対象カレンダーはメインカレンダーのみ**(`CalendarApp.getDefaultCalendar()`)。ただし設定シート `calendarIds`(カンマ区切りID)が非空ならそれらを追加対象にする仕組みも入れる(一覧にカレンダー名を表示)
3. 時間付きイベントは**30分丸め**でグリッドへ: 開始=切り下げ、終了=切り上げ
4. 記憶が無いイベントは**チェックOFFが既定**(勝手に取り込まれない)。記憶があるものはチェックON+区分自動選択

## UI仕様(取込モーダル)

- ツールバーの「取込」ボタン(`#btn-import`、現在disabled)を有効化し、クリックで開く
- 既存の共通モーダル(`#modal-overlay`/`#modal`)を使う。**Esc・オーバーレイクリックで閉じる**(統一ルール。既存実装に乗るだけで満たせる)
- 開いたら `listCalendarEvents(state.ym)` を呼び、ローディング表示→一覧を描画
- 一覧テーブルの列:
  1. チェックボックス
  2. 日時: `7/23(木) 09:15-10:00`。終日イベントは `7/23(木) 終日`
  3. タイトル
  4. 割当: 時間付き→区分セレクト(有効な大区分を optgroup、内訳を子option。値は `"CODE"` または `"CODE|SUB"`)。終日→固定表示「日メモとして取込」
  5. 状態: 取込先スロットに既存記録がある場合「上書き」バッジ(`.imp-overwrite`)。表示時間帯(dayStart前/dayEnd後)にはみ出す場合「⚠時間帯外含む」注記
- 記憶(取込対応シート)にタイトルが一致する行: チェックON+区分(または日メモ)を自動設定
- フッター: 「N件選択中」表示+「キャンセル」「取込実行」ボタン
- 取込実行後: モーダルを閉じ、グリッド・集計を再描画し、トースト「N件取り込みました」

## 丸め・反映仕様

- 開始時刻: 30分単位に**切り下げ**(9:15→9:00)。終了時刻: **切り上げ**(17:45→18:00)
- 開始=終了になる場合(0分イベント)は最低1スロット(開始スロットのみ)
- 日またぎイベントは**開始日の23:59まで**で打ち切り(翌日分は生成しない。まれなケースのため単純化)
- グリッド表示時間帯外のスロットも**生成する**(仕様書9章の既存仕様: 表示されないが集計に含まれる)。一覧に注記を出す
- スロット生成: `{code, sub, memo: ""}` で既存スロットを**上書き**(チェックした=上書き了承。「上書き」バッジで事前に見えている)
- 終日イベント→日メモ: 既存の日メモに「・」区切りで**追記**。ただし**同じ文字列が既に含まれていたらスキップ**(再取込しても重複しない=冪等)
- 反映は楽観更新: state更新→`markRecordsDirty()`/`markDaysDirty()`(変わった方だけ)→既存のデバウンス保存に乗せる

## Undo対応

- 取込実行の直前に**1回だけ**スナップショットを積み、取込全体が1回のUndoで戻るようにする
- 現在の `pushUndo(kind)` は kind が `"records" | "days"` で、undo時にどちらを再保存するか判別している。取込は両方変わりうるため **kind `"both"` を追加**し、`undo()` で `"both"` のとき `markRecordsDirty()` と `markDaysDirty()` を両方呼ぶよう拡張する
- 注意: 取込対応シート(記憶)の保存はUndo対象外でよい(記憶が残っても実害なし。仕様書に明記する)

## データ・API仕様

### 取込対応シート(既存: [タイトル, 区分, 内訳])
- 時間付きイベント: `[タイトル, 区分コード, 内訳コード]`
- 終日イベント(日メモ取込): 区分コード列に**予約語 `DAYMEMO`** を入れる(`[タイトル, DAYMEMO, ]`)
- タイトル完全一致で upsert(既存タイトル行は上書き、無ければ末尾追加)
- 列の追加・順序変更は禁止(既存ルール)

### GAS API追加(2つ。doPost の API マップに登録すること)

```
listCalendarEvents(ym)
  → { events: [{ title, start: "yyyy-MM-dd HH:mm", end: "yyyy-MM-dd HH:mm",
                 allDay: bool, date: "yyyy-MM-dd",   // allDay用・開始日
                 calendarName: "..." }],
      importMap: { "タイトル": { code, sub } } }     // DAYMEMO は code:"DAYMEMO"
```
- 対象: `getDefaultCalendar()` + `calendarIds`(設定、カンマ区切り、空要素は無視)の各 `getCalendarById()`(取得失敗したIDはスキップ。落とさない)
- 期間: その月の1日0:00〜翌月1日0:00(`cal.getEvents(from, to)`)
- 終日判定: `ev.isAllDayEvent()`。終日の date は `ev.getAllDayStartDate()` を `fmtDate_` で
- 複数日にわたる終日イベントは開始日のみでよい
- ソート: 日時昇順
- **祝日カレンダーは対象に含めない**(祝日は別機能で取得済み)

```
saveImportMap(entries)   // [{title, code, sub}]
  → { ok: true, count }
```
- タイトルで upsert。entries が空なら何もしない
- 書き込みは既存の `writeAllRows_` パターンに合わせる(全読み→マージ→書き戻し)

### フロント(app.js)
- `serverCall("listCalendarEvents", ym)` / `serverCall("saveImportMap", entries)`
- 取込実行の流れ:
  1. チェック済み行を収集(時間付き: 区分未選択の行があればトースト警告で中断)
  2. `pushUndo("both")`
  3. 時間付き→丸めてスロット生成し `state.records` 上書き / 終日→`state.days[date].memo` へ冪等追記
  4. `markRecordsDirty()`(スロットを生成した場合)/ `markDaysDirty()`(日メモを変えた場合)
  5. `saveImportMap(チェック済み全件)`(時間付きは選択区分、終日は `DAYMEMO`)— 失敗しても取込自体は成立(トーストのみ)
  6. `closeModal()` → `renderGrid()` `renderSummary()` → トースト

### モック(preview/mock.js)
- `listCalendarEvents`: 表示月に応じたサンプルを動的生成(検証ケースを網羅する):
  - 「出勤」9:15-17:45(丸め検証: →9:00-18:00)
  - 「歯医者」14:00-15:00(既存スロットと重ねる日を選ぶと上書きバッジ検証になる)
  - 「燃えるごみ」終日(毎週火曜相当で2-3件)
  - 「歓迎会」18:30-20:30
  - 「早朝会議」5:30-6:30(時間帯外注記の検証)
- `importMap` は db.importMap(localStorage)から返す。`saveImportMap` で upsert
